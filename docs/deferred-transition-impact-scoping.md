# 전면 deferred 전환 — 투명·라이트맵·Forward Mobile 영향 스코핑 (§11-6)

> **상태: v1.1 (2026-08-25) — L1(C1) 검토 반영: 채널 예산 정정.** 로드맵 §11 조기 결정 6번("어느 문서에도 견적이 없다")을 닫는 문서. G1 동결의 전제 자료이며, L1 담당자(C1)의 검토·보강 대상.
> 실측 기준: `render_forward_clustered.cpp` / `scene_forward_clustered.glsl` (master).

## 0. 결론 요약

| 축 | 판정 | 규모 |
|---|---|---|
| 투명(알파) 패스 | **포워드 유지 확정** — 전 엔진 공통 구조. 재작성 아님, *공존 배선* | 🟡 수 주 |
| 라이트맵/SH | **deferred 편입 필요** — shading-model-ID 채널이 강제됨(G1이 이미 예약) | 🟡 1~2개월 |
| Forward Mobile | **비전환 동결 제안** — 포크 타깃(데스크톱+콘솔+macOS)에서 유지 부담만 발생 | ⚪ 결정 필요 |
| SSS/스페큘러 후처리 | 리졸브 재배선 | 🟢 수 주 |

**총 견적: L1 2~4개월 (S4 리졸브 본체와 병행 가능한 부분 다수).** "전면 deferred"의 정확한 의미는 **"opaque 전면 deferred + 투명 포워드 공존"**이다 — UE/Frostbite와 동일 구조.

## 1. 투명 패스 — 유지되지만 공짜가 아니다

`RENDER_LIST_ALPHA`는 역깊이 정렬(`:1929`) 후 `PASS_MODE_COLOR`로 별도 드로우(`:2437`). deferred 전환 후에도 이 경로는 그대로 살아야 한다. **실비용은 3가지 공존 배선:**

1. **패스 순서 재정의**: GBuffer emit → deferred 리졸브 → **투명 포워드** → 포스트. 투명이 리졸브 결과(오패시티 뒤 씬 컬러)와 `gb_depth`를 소비.
2. **라이팅 자원 이중 소비**: 투명 포워드는 클러스터 라이트 구조(`ClusterBuilderRD`)를 계속 쓴다 — 리졸브 컴퓨트도 같은 froxel을 쓰므로(**nanite-perf §4-3 "froxel 재사용" 그대로**) 자원은 공유되고 바인딩만 이중화. **클러스터 빌더는 삭제 불가.**
3. **셰이더 변종 유지**: `scene_forward_clustered.glsl`의 풀 라이팅 루프가 투명 전용으로 축소 유지 — opaque 라이팅 루프 제거 시 `#ifdef` 경계를 투명 기준으로 재긋기.

**리스크**: refraction(스크린 컬러 리드)이 리졸브 이후 시점으로 이동 — 현재와 동일 시맨틱이라 낮음.

## 2. 라이트맵/SH — 이번 스코핑의 실질 발견

포워드 셰이더에 라이트맵 참조 53건. 두 갈래로 갈라진다:

- **(a) 라이트맵 샘플 자체** (`USE_LIGHTMAP`, SH 포함): deferred에서는 리졸브가 샘플해야 하나 **리졸브는 UV2·라이트맵 슬롯을 모른다.** ②(리졸브 샘플) 권고 유지 — 단 **채널 배치는 v1.1에서 정정(C1)**: ~~R8_UINT + UV2를 Tier-2로~~ 는 성립 불가(UV2는 라이트맵 지오메트리 필수 입력이라 게이트 채널일 수 없고, MRT 9번째가 됨). **채택안: 8번째 슬롯에 단일 `gb_shading_control` RG32_UINT** — `.x` = shading-model-ID(8b) | 라이트맵 슬롯(8b) | 플래그(16b, (b)의 bake-skip 비트 포함), `.y` = UV2 packed 16:16 unorm(4096² 아틀라스에 충분). **대역폭: 36→44 B/px(+22%), 1080p 92MB·4K 367MB** — 라이트맵 편입 활성 시에만.
- **경계 명문화 (C1)**: 이 시점에 비-Nanite 래스터 emit은 **8/8 영구 포화**다. 이후 per-pixel 요구는 기존 채널 대체 또는 컴퓨트 emit 전환을 강제한다.
- **전제 명문화 (L2 교차 확인 대기)**: **Nanite 지오메트리는 베이크 라이트맵을 쓰지 않는다.** 이 배제로 Nanite 리졸브에 UV2가 불요해 1슬롯 안이 성립하며, 허용으로 뒤집으면 G2 지오 풀 정점 요구에 UV2 추가 = G2 계약 변경이다.
- **(b) 정적 베이크 라이트 스킵 로직** (`:579,:614` — bake_mode STATIC && USE_LIGHTMAP 시 실시간 라이트 스킵): 리졸브의 라이트 루프가 같은 판정을 해야 **이중 조명**이 안 생긴다. per-pixel 플래그가 필요 — shading-model-ID 바이트의 1비트로 충분.

**결론: 라이트맵 편입은 shading-model-ID 채널 추가를 강제하며, 이는 G1 재개정이 아니라 G1이 예약한 확장의 행사다.** GI(SDFGI/VoxelGI 19건 참조)도 같은 구조로 리졸브 이관 — L3의 Milestone B와 동일 작업면이라 중복 없음.

## 3. Forward Mobile — 결정 요청

`forward_mobile/`은 별도 렌더러로 존재. 포크 확정 타깃(데스크톱 3API + 콘솔 + macOS 출하)에 모바일이 없다. 선택지:
- **(A) 비전환 동결 — v1.1에서 기본값 확정 (C1 검토 채택)**: 비용 0·기존 전제 정합·되돌림 자유. GBuffer 계열 신기능은 Forward Mobile 영구 미지원 명시. **사용자 질의 불요** — 모바일 출하가 실제 안건이 될 때만 재개봉. (B) 삭제는 그 시점 논의.

## 4. SSS·기타 후처리

SSS는 이미 화면공간 후처리(`sub_surface_scattering`, `:1712`)라 구조 유지 — 입력이 포워드 출력에서 리졸브 출력으로 바뀔 뿐. `gb_orm.a`(sss-mask)가 G1에 이미 있어 마스크 전달도 해결. 투명+SSS 비호환(`:1976`)은 현 제약 그대로 승계.

## 5. G1에의 피드백

이 스코핑으로 G1 동결 전 확정이 필요해진 것: **없음.** shading-model-ID는 예약 확장 행사로 충분하고, UV2는 Tier-2. **G1은 이 문서와 독립적으로 동결 가능하다** — C1 서명만 남음.
