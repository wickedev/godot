# W4 Games 접촉 질의서 + 콘솔 등록 준비 체크리스트 (§11-2·3)

> 로드맵 §11 조기 결정 2·3번 실행 준비 문서. 2026-08-25 작성.
> **외부 접촉·등록은 사용자 실행 항목** — 이 문서는 그 준비물이다. 근거: [console 리서치](./godot-console-export-research.md) §5~§7.

## 1. 전제 (이 프로젝트 특수 사정)

W4의 표준 모델은 **"대체로 unmodified Godot 실행"** 전제다. 우리는 업스트림 디스커넥트 포크에 침습적 코어 개조(RDD 인터페이스 변경·async compute 렌더그래프 재작업·bindless 포함)를 하므로 **표준 drop-in이 성립하지 않을 가능성이 높다.** 질의의 핵심은 "포크에도 W4 모델이 유효한가"이다.

## 2. W4 질의 목록 (계약 전 확인 필수)

| 1 | **커스텀 포크 지원 범위** — RDD 136-메서드 인터페이스가 변경된 포크에 포트 소스 제공/통합 지원이 가능한가? 지원 불가 경계는 어디인가? | 프로젝트 전제 자체. 불가 시 직접 포팅 경로로 전환 |
| 2 | 포트 소스·문서 제공 범위와 구독 종료 후 사용권 | 포크 유지보수는 우리가 하므로 소스 접근이 필수 |
| 3 | **Steam Audio 자가 포팅 콘솔 인증 선례/제약** — 오디오 미들웨어 확정(2026-08-25): Steam Audio 벤더링. 콘솔 인증에서 서드파티 오픈소스 DSP가 문제된 사례가 있는가? | 오디오 전략의 유일 잔여 리스크 |

| 8 | 인증 재제출 시 W4 관여 범위 (deep-core 포크에서 재현 불가 이슈의 책임 경계) | 유지보수 비용 |

## 4. NDA 불요 선행 작업 (console 리서치 §6 — 이미 로드맵에 편성된 것 제외)

- 플랫폼 추상화 준수 감사: `OS`/`DisplayServer`/`RenderingDeviceDriver` 밖으로 새는 플랫폼 가정이 없는지 — **L1 코어 개조가 진행될수록 이 감사가 중요해짐** (개조가 seam을 넘으면 콘솔 포팅 비용이 증폭).
- 빅엔디언/얼라인먼트 가정 제거는 불요(현세대 콘솔 전부 x86/ARM LE) — 대신 **페이지 크기·메모리 예산 가정**을 상수화할 것.
