# Godot 4.x 가상 텍스처링 — 구현 계획서

> 이 문서는 **실행 계획서**다. 배경·검증 근거는 [`godot-virtual-texturing-research.md`](./godot-virtual-texturing-research.md)에 있고, 여기서는 "무엇을, 어떤 순서로, 무엇을 검증하며" 만들지에 집중한다.
> 대상: 젠신급 스타일라이즈드 오픈월드. 엔진: Godot 4.x (Forward+).
> 작성일: 2026-08-03.

## 0. 전략 요약

- **P0 타깃 = RVT식 런타임 캐시.** 하드웨어 스파스 바인딩이 필요 없고, AAA 오픈월드의 지형-오브젝트 블렌딩 병목에 직접 대응하며, 기존 RenderingDevice 컴퓨트 + 논블로킹 리드백으로 코어 개조 없이 프로토타입 가능. **단, RVT는 지형 블렌딩만 커버 — 캐릭터 유니크·무기 스킨·건축물 유니크 텍스처는 별도 트랙 필요.**
- **P1 병행 = 소프트웨어 SVT(스트리밍) + 하드웨어 스파스 VT.** AAA 유니크 텍스처 예산 감당. SW SVT는 GDExtension 범위, HW 스파스는 코어 C++ 개조(bounded, man-year 아님). 둘 다 AAA에서 선택이 아닌 필수.
- **P2 = PR #113429 머지/포워드포팅.** 업스트림 공식 텍스처 밉레벨 스트리밍을 자체 VT의 하위 인프라로 활용.

**의사결정 게이트**: Phase 0 스파이크 3건의 결과가 이후 아키텍처를 확정한다. 스파이크 전에 스트리밍 스레딩 모델을 못박지 말 것.

## Phase 0 — 정찰 스파이크 (게이팅, ~1~2주)

각 스파이크는 **작은 실증 코드 + 판정 문서**로 끝난다. 목적은 "만들기"가 아니라 "리스크 제거".

### S0.1 — 논블로킹 리드백 왕복 실증
- **목표**: `RenderingDevice.buffer_get_data_async(rid, callback, offset, size)`로 GPU 버퍼를 스톨 없이 CPU로 받는 왕복을 GDScript/GDExtension에서 성공시킨다.
- **방법**: 컴퓨트 셰이더가 SSBO에 "가짜 페이지 요청" 목록을 기록 → async 리드백 → 콜백에서 파싱.
- **판정 기준(Go/No-Go)**: 콜백이 후속 프레임에 호출되고, 메인 스레드 프레임타임 스파이크가 없다.
- **근거**: 선언 `servers/rendering/rendering_device.h:268-269`, 구현 `rendering_device.cpp:1329-1409`.

### S0.2 — 스레드 가드(#99750) 현재 상태 확인
- **목표**: 현재 사용 중인 Godot 버전(4.4/4.5 master)에서 **백그라운드 스레드**의 텍스처/버퍼 RD 호출이 허용되는지, 승인된 대체 경로가 있는지 확정.
- **방법**: 워커 스레드에서 텍스처 업데이트 + async 리드백을 시도 → 스레드 가드 assert 여부 관찰.
- **판정 기준**: (A) 백그라운드 허용 → 워커 기반 스트리밍 설계 채택. (B) 차단 → 메인 스레드 큐잉 + 시간분할(time-slice) 설계로 폴백.
- **근거**: 이슈 <https://github.com/godotengine/godot/issues/99750>. **버전마다 다를 수 있으니 반드시 실측.**

### S0.3 — bindless / Forward+ 합성 조사
- **목표**: (a) RenderingDevice가 descriptor indexing(비균일 인덱싱, update-after-bind)을 익스텐션에 노출하는가? (b) 커스텀 RD 패스를 렌더러 포크 없이 지형 머티리얼 경로에 합성 가능한가?
- **방법**: 셰이더에서 텍스처 배열 인덱싱 시도 + `CompositorEffect`/커스텀 셰이더로 지형 머티리얼에 VT 샘플 주입 실험.
- **판정 기준**: bindless 불가 시 → 소프트웨어 VT는 단일 물리 아틀라스 텍스처 + UV 인디렉션 방식으로 축소 설계.
- **근거**: reduz GPU-driven 방향 <https://gist.github.com/reduz/c5769d0e705d8ab7ac187d63be0099b5> (아직 익스텐션 노출은 미확인 = open question).

**Phase 0 산출물**: `docs/vt-spike-report.md` — 3건의 Go/No-Go 판정과 그에 따른 Phase 1 아키텍처 확정.

## Phase 1 — RVT식 런타임 캐시 (1순위, 코어 개조 없음)

### 목표
지형 머티리얼의 셰이딩 결과를 넓은 영역에 걸쳐 **런타임 GPU 캐시**에 굽고, 오브젝트·데칼·스플라인을 같은 캐시에 합성해 지형과 이음새 없이 블렌딩한다. (UE RVT의 지형 유스케이스 재현)

### 구성요소
1. **RVT Asset(물리 아틀라스)**: 고정 크기 RD 텍스처(예: 4K/8K), 페이지 그리드로 분할. 알베도/노멀/러프니스 등 채널.
2. **인디렉션 텍스처(페이지 테이블)**: 월드 타일 좌표 → 아틀라스 페이지 좌표 매핑. 저해상도 R16/RG16 텍스처.
3. **Write 경로**: 카메라 독립 셰이딩(지형 스플랫 블렌딩)을 컴퓨트/드로우로 아틀라스 페이지에 렌더 → 매 프레임 전부가 아니라 필요한 페이지만.
4. **Read 경로**: 지형/오브젝트 머티리얼 셰이더가 인디렉션을 통해 아틀라스를 샘플.
5. **갱신 정책**: 카메라 이동에 따라 가시 페이지 세트 갱신, LRU로 페이지 재활용.

### 검증
- 지형 위 오브젝트 하단이 지형 텍스처로 블렌딩되는지 시각 확인.
- 카메라 이동 시 페이지 재사용으로 아틀라스 크기가 상수로 유지되는지 계측.
- 프레임타임: 매 프레임 전체 지형 재셰이딩 대비 이득 측정.

### 산출물
- GDExtension: `VirtualTextureRuntime`(캐시 관리) + 지형 셰이더 통합 예제 씬.

## Phase 2 — 소프트웨어 SVT (스트리밍, 코어 개조 없음)

### 목표
디스크의 초대형 유니크 텍스처를 타일 단위로 온디맨드 스트리밍. VRAM 예산을 물리 아틀라스 크기로 고정.

### 구성요소 (Barrett stb SVT 참조)
1. **가상 텍스처 정의**: 타일 그리드 + 밉 피라미드. 디스크에 타일 단위(예: 128²) 저장.
2. **피드백 패스**: 프래그먼트 셰이더가 이번 프레임에 필요한 (타일ID, 밉) 을 SSBO에 기록.
3. **분석/리드백**: `buffer_get_data_async`로 피드백 SSBO를 CPU로 → 필요 타일 집합 산출(S0.1 왕복 재사용).
4. **스트리머**: 디스크→스테이징→물리 아틀라스 타일 업로드. 스레딩 모델은 S0.2 결과에 따름.
5. **인디렉션 갱신**: 새 타일이 아틀라스에 들어오면 페이지 테이블 갱신.
6. **셰이더 주소 변환**: virtual UV → 인디렉션 룩업 → physical UV. 밉 경계·이방성 처리 주의.

### 리스크 & 우회
- **스트리밍 팝인/블러**: 저밉 폴백 + 우선순위 큐로 완화(제거 불가, §research §1.1 주의).
- **아틀라스 이음새/필터링**: 타일 경계 보더(gutter) 픽셀 추가.
- **스레드 가드**: S0.2가 (B)면 스트리머를 메인 스레드 시간분할로.

### 산출물
- GDExtension: `VirtualTextureStreaming` + 오프라인 타일 베이커(CLI) + 데모.

## Phase 3 — 하드웨어 스파스 VT (코어 C++ 개조, P1 병행)

> **이 단계는 코어 C++ 개조를 필요로 하나, 포크 전제에서는 bounded engineering 작업이다 (man-year 아님).** Phase 1/2와 병행 추진. clayjohn의 "Vulkan sparse textures is known to not be well performant on PC" 경고는 드라이버별 벤치마크로 해소할 엔지니어링 리스크.

### 코어 변경 항목
1. **Vulkan device 피처 활성화**: `drivers/vulkan/rendering_device_driver_vulkan.cpp`(~L818-826)에서 `sparseBinding`·`sparseResidencyImage2D` 등을 조건부 활성화(가용성 쿼리 후).
2. **RenderingDevice API 추가**: sparse image 생성, `vkQueueBindSparse` 상당의 타일 (언)바인딩 엔트리포인트, D3D12 `UpdateTileMappings`·Sampler Feedback 상당 경로.
3. **크로스 백엔드**: Vulkan / D3D12 / **Metal**(4.4+ 네이티브 RD 드라이버, sparse texture/heap 등가물 — 현재 검증 소스 공백, 별도 조사 필요)에 균일 노출.
4. **상류 기여**: Godot 제안 [#1834](https://github.com/godotengine/godot-proposals/issues/1834)에 맞춰 설계 리뷰.

### 산출물
- 코어 패치(포크) + RenderingDevice sparse API + 하드웨어 백킹 VT.

## 마일스톤 & Go/No-Go

1. **M0 (Phase 0 완료)**: 스파이크 3건 판정 → 스트리밍/합성 아키텍처 확정. *No-Go 시*: 소프트웨어 경로도 막히면 §gaps 원래 "수동 아틀라스" 대안으로 회귀.
2. **M1 (Phase 1 MVP)**: 지형 위 오브젝트 RVT 블렌딩 데모 + 상수 아틀라스 검증. → 젠신급 지형 병목 1차 해소.
3. **M2 (Phase 2 MVP)**: 단일 초대형 텍스처 스트리밍 데모 + 팝인 허용 범위 확인.
4. **M3 (Phase 3 결정 게이트)**: Phase 1/2로 요구 충족 여부 재평가 → HW 스파스 착수/보류 결정.
