# 오디오 미들웨어 × 콘솔 — 결정 브리핑 (§11-1)

> 로드맵 §11 조기 결정 1번(리스크 🔴, "가장 늦게 발견하면 가장 비싼 종류의 제약"). 2026-08-25 웹 실사 + 로컬 실측 기반. **결정권자: 사용자.**

## 1. 사실관계 (실사로 정정된 것)

audio 문서 §0의 *"셋 다 콘솔을 지원하지 않는다"* 는 **부정확**했다. 정확한 그림:

| | Wwise/FMOD | Steam Audio |
|---|---|---|
| 미들웨어 본체 콘솔 지원 | ✅ PS5/Xbox/Switch 공식 (콘솔 개발자 등록 필요) | ⚠️ 공식 콘솔 빌드 없음. 단 **Apache-2.0 전체 소스** → 자가 포팅 가능 |
| **Godot 통합 레이어** 콘솔 지원 | ❌ 커뮤니티 GDExtension은 데스크톱/모바일/웹뿐 | ❌ 동일 |
| W4 콘솔 포트와의 번들 | 명시 없음 — 계약 시 확인 필요 | 해당 없음 |

**병목은 라이선스가 아니라 "Godot 통합 레이어의 콘솔 재빌드가 상품화돼 있지 않다"는 엔지니어링 갭이다.** 포크 전제에서 이것은 우리가 늘 하는 종류의 일이다.

## 2. 분업 구조 (어느 쪽을 골라도 변하지 않는 것)

- **§6(디스크 스트리밍·보이스 매니저·믹스 멀티스레딩)은 Steam Audio가 못 푼다** — 공간화 엔진이지 스트리밍 엔진이 아니다. Wwise/FMOD만 §6을 통째로 제공.
- **§2(오클루전·회절·전파)는 Steam Audio 하나로 닫힌다.** 자작은 man-year(= Steam Audio 재발명).
- 자작 §6 견적: 무음 디코드 스킵(수일) + 보이스 매니저(2~3주) + 믹스 스레딩(2~6주) + 디스크 스트리밍(1~3개월) ≈ **2~4개월** — 이미 로드맵 L8 Wave 2에 편성돼 있음.

## 3. 선택지

### A. Steam Audio 벤더링 + §6 자체 구현 (제안)
- **정합성:** 포크·업스트림 디스커넥트·"전부 구현" 전략과 동형. Apache-2.0 소스를 thirdparty로 벤더링 — 다른 서브시스템과 같은 취급. 클로즈드 의존 0.
- **콘솔:** 소스 자가 포팅(CPU DSP라 이식성 높음). 단 **콘솔 인증 통과 선례가 공개돼 있지 않음** — 리스크.
- **비용:** §6 자체 구현 2~4개월(편성됨) + Steam Audio 통합 수 주 + 콘솔 포팅 시 추가.
- **포기하는 것:** Wwise급 저작툴(사운드 디자이너 워크플로) — 저작 UX는 L7식 EditorPlugin으로 별도 구축 필요.

### B. Wwise (또는 FMOD) 풀 미들웨어
- **정합성:** §2+§6을 한 번에 닫음. 사운드 디자이너 저작툴 최상.
- **콘솔:** 벤더 공식 지원이나 **Godot 통합의 콘솔 빌드는 우리 몫**(수 주) + W4 포트와의 조합 검증 필요.
- **비용:** 라이선스(타이틀당) + 클로즈드 의존 — 포크 철학과 이질적. 엔진 딥 개조(단일 오디오 스레드 → Wwise 자체 스레딩)와의 접점 관리.
- **포기하는 것:** 오디오 스택 소유권. §6 코어 개조 무의미화(이중 투자 방지 위해 L8 Wave 2 항목 취소 필요).

### C. 전부 자작 (§2 포함)
- "전부 구현"의 극단 해석. §2 자작 = man-year 재발명(Steam Audio가 Apache-2.0인데). **비권장 — 오배분.** 미들웨어 탈락 시 최후 폴백으로만.

## 4. 권고

**A (Steam Audio 벤더링 + §6 자체 구현).** 근거: ① 포크 전략과 정합 ② §6 자체 구현이 이미 로드맵에 편성돼 있어 증분 최소 ③ 클로즈드 의존 없이 콘솔 경로 통제 가능 ④ C 대비 man-year 절약. 콘솔 인증 선례 부재 리스크는 W4 계약 시 Steam Audio 포팅 가능 여부를 질의 항목에 포함해 조기 해소.

**결정 시한: L8이 §6 착수하는 Wave 2 진입 전.** 단 B를 택하면 L8 Wave 2 편성이 통째로 바뀌므로 빠를수록 좋다.
